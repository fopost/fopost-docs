Every network below is connected once in the dashboard and published to from anywhere: the composer, the [API](/api/overview), the [SDKs](/sdks/overview), the [CLI](/cli), or the [FoPost Agent](/guide/using-fopost/agent). Every account gets every network — there is no tier that unlocks more of them.

The limits in these tables are the ceilings FoPost enforces before a post ever leaves, so the composer flags an over-long caption or an oversized file instead of letting the network reject it.

"Analytics" means FoPost can read per-post or account metrics back from the network; the [analytics guide](/guide/using-fopost/analytics) covers exactly which numbers each one reports. Instagram is one network however you connect it, and post scheduling works everywhere — scheduling is FoPost's, not the network's.

## How a post is delivered

Most networks publish server side through their own API. You connect once, and scheduled posts go out whether or not your browser is open.

A network with no write API cannot work that way, and driving a headless browser at one is against its terms. For those, FoPost stages the post and the [browser extension](/sdks/browser-extension) publishes it from your own logged-in session, in one click. Substack is the network that goes through this today.

An extension delivery is still a delivery: it shows on the calendar, in the history, and in analytics like any other.

## Connecting

Every network is connected in **Accounts → Connect**. Most use that network's own authorisation screen — FoPost never asks for your password there. The rest authenticate the way the network itself prescribes: an app password for Bluesky, a bot token for Telegram, a channel webhook for Discord, an API key for DEV.to and Hashnode, your own instance details for self-hosted networks like Mastodon, Lemmy, and Listmonk. See [Connecting Accounts](/guide/using-fopost/connecting-accounts) for each network's requirements.
