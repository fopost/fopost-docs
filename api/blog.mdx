The blog writes articles for a website, not posts for a network. You describe the site once, a keyword plan fills a calendar, the writer drafts each article in the background, and after a review window the draft publishes to the target you chose: a connected account, your own website, or the product blog.

Every route lives under `/v1/blog`, takes a `workspaceId` (in the query for `GET`, `PATCH` and `DELETE` routes with an id, in the body otherwise) and answers in the usual `{ "data": ... }` envelope. All fields are camelCase.

| Scope | Covers |
|:------|:-------|
| `posts` | Reading anything, settings, keyword edits, editing, rejecting and deleting articles |
| `ai` | Anything that spends AI credits: planning keywords, requesting an article, regenerating one |
| `publish` | Publishing an article |

## How an article moves

```
suggested keyword → planned → queued → writing → draft → scheduled → publishing → published
```

1. **Plan.** `POST /keywords/plan` researches keywords for the site and marks the best ones `planned`, each with a `plannedFor` date. You can add your own with `POST /keywords`
2. **Write.** When a planned date comes within `reviewHoldDays`, or when you call `POST /articles`, the writer runs in the background: research, outline, body, meta and images. The article is `queued`, then `writing`, then lands as a `draft`
3. **Review.** A draft waits until `reviewUntil`. Edit it, reject it, or publish it early. With `autoPublish` on, a draft that nobody touched publishes on its own when the window closes
4. **Publish.** The article goes to the target. `scheduled` means a date is set, `publishing` means the send is in flight, `published` means it landed, with `publishedUrl` when the target reported one

| Article status | Meaning |
|:---------------|:--------|
| `queued` | Waiting for the writer |
| `writing` | The writer is running |
| `draft` | Written, in review until `reviewUntil` |
| `scheduled` | Will publish at `publishAt` |
| `publishing` | Being sent to the target |
| `published` | Live. `publishedAt` is set, `publishedUrl` when known |
| `failed` | The write or the publish failed; `error` says why. Edit and publish again, or regenerate |
| `rejected` | Rejected by a reviewer. It stays readable and can be edited back into review |

Keyword statuses are `suggested`, `planned`, `written` and `dismissed`.

## Targets

One target per workspace, set in the settings. Without one, every publish answers `409 no_target`.

| `targetKind` | Where the article goes |
|:-------------|:-----------------------|
| `account` | A connected account (`targetAccountId`), published as an article post on that network. Pick an account on a network that takes articles, such as WordPress, Medium, dev.to, Hashnode or Listmonk |
| `website` | Your own site. The article is `POST`ed to `websiteUrl` as a signed `article.published` payload. See [receiving blog articles](/guide/receive-blog-articles) |
| `product_blog` | The FoPost product blog. Available to admins only |

Whatever the target, the workspace's [webhooks](/webhooks/events#articles) receive `article.published` as well.

## Settings

```http
GET /v1/blog/settings?workspaceId=
```

```bash
curl "https://api.fopost.com/v1/blog/settings?workspaceId=7d2b8c11-4e5a-4a8f-b0d9-3c5e6f7a8b90" \
  -H "X-API-Key: $FOPOST_API_KEY"
```

```json
{
  "data": {
    "siteUrl": "https://yourbrand.com",
    "topic": "Running shoes and training plans",
    "audience": "Amateur runners training for their first marathon",
    "language": "en",
    "locationCode": 2840,
    "cadencePerWeek": 2,
    "reviewHoldDays": 3,
    "autoPublish": false,
    "imageTier": "standard",
    "inBodyImages": 2,
    "minWords": 1200,
    "maxWords": 1800,
    "brandVoiceId": "0a1b2c3d-4e5f-4a6b-8c7d-9e0f1a2b3c4d",
    "targetKind": "website",
    "targetAccountId": null,
    "targetPlatform": null,
    "websiteUrl": "https://yourbrand.com/api/fopost/articles",
    "hasWebsiteSecret": true,
    "keywordDataAvailable": true,
    "updatedAt": "2026-10-01T08:12:00.000Z"
  }
}
```

| Field | Description |
|:------|:------------|
| `siteUrl`, `topic`, `audience` | What the site is about and who reads it. The planner derives its seed keywords from these when you pass none |
| `language`, `locationCode` | Language of the articles and the market keyword data is read for |
| `cadencePerWeek` | Articles planned per week, 0 to 7. `0` turns planning off |
| `reviewHoldDays` | How long a draft waits in review, 0 to 14 days. Writing starts this many days before the planned date, so the draft is reviewable for the whole window and publishes on the day |
| `autoPublish` | Publish a draft on its own when its review window closes. Needs a target |
| `imageTier` | `draft`, `standard` or `best`, the quality tier for generated images |
| `inBodyImages` | Images placed under outline headings, 0 to 3, on top of the featured image |
| `minWords`, `maxWords` | The length the writer aims for |
| `brandVoiceId` | The [brand](/guide/brand-voices) the writer writes in |
| `targetKind`, `targetAccountId`, `websiteUrl` | The target, above. `targetPlatform` is read-only and names the target account's network |
| `hasWebsiteSecret` | Whether a website signing secret exists. The secret itself is never readable |
| `keywordDataAvailable` | Whether search volume and difficulty can be fetched on this deployment |

### Update settings

```http
PATCH /v1/blog/settings
```

```bash
curl -X PATCH "https://api.fopost.com/v1/blog/settings" \
  -H "X-API-Key: $FOPOST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "workspaceId": "7d2b8c11-4e5a-4a8f-b0d9-3c5e6f7a8b90",
    "targetKind": "website",
    "websiteUrl": "https://yourbrand.com/api/fopost/articles"
  }'
```

```json
{
  "data": { "targetKind": "website", "websiteUrl": "https://yourbrand.com/api/fopost/articles", "hasWebsiteSecret": true, "...": "..." },
  "websiteSecret": "whsec_K3n9xq2YpB7vLh0dR4sWfT8mZc1aE6uJ"
}
```

Every field is optional except `workspaceId`; send the ones you want to change. Setting `websiteUrl` for the first time issues a signing secret, returned once as `websiteSecret` beside `data` and `null` on every other update. Clearing `websiteUrl` drops the secret. `targetKind: "product_blog"` answers `403` unless the key belongs to an admin.

### Rotate the website secret

```http
POST /v1/blog/settings/website-secret
```

```json
{ "data": { "websiteSecret": "whsec_Q8vL2mB5xN1tY7cR0wP4kH9sA3dF6gJz" } }
```

Body `{ "workspaceId": "..." }`. The old secret stops verifying immediately, and the new one is shown once.

### Test the website

```http
POST /v1/blog/settings/website-test
```

Body `{ "workspaceId": "..." }`. Sends a signed `article.test` envelope to `websiteUrl` and reports what the site said.

```json
{ "data": { "ok": true, "status": 200, "error": null } }
```

The response is `200` when the site accepted it and `502` when it did not, with `status` set to what the site answered (or `null` when nothing came back) and `error` saying why.

## Keywords

```http
GET /v1/blog/keywords?workspaceId=
```

| Parameter | Description |
|:----------|:------------|
| `workspaceId` | Required |
| `status` | Comma-separated: `suggested`, `planned`, `written`, `dismissed` |
| `limit` | Caps the list |

```json
{
  "data": [
    {
      "id": "3f8a1d92-6c40-4b7e-a15d-90b2c4e6f8a1",
      "keyword": "marathon training plan for beginners",
      "searchVolume": 9900,
      "difficulty": 42,
      "cpc": 1.35,
      "intent": "informational",
      "source": "provider",
      "status": "planned",
      "plannedFor": "2026-10-14",
      "createdAt": "2026-10-01T08:15:00.000Z"
    }
  ]
}
```

`searchVolume`, `difficulty` (0 to 100), `cpc` and `intent` are `null` when the deployment has no keyword data (`keywordDataAvailable` is `false`) or the keyword was added by hand. `source` is `provider`, `user` or `agent`.

### Plan keywords

```http
POST /v1/blog/keywords/plan
```

```bash
curl -X POST "https://api.fopost.com/v1/blog/keywords/plan" \
  -H "X-API-Key: $FOPOST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "workspaceId": "7d2b8c11-4e5a-4a8f-b0d9-3c5e6f7a8b90", "seeds": ["marathon training", "running shoes"] }'
```

```json
{ "data": { "status": "queued" } }
```

Answers `202` and runs in the background: it researches the seeds (derived from `siteUrl`, `topic` and `audience` when omitted), stores the results as `suggested`, and marks enough of them `planned` to fill the calendar at `cadencePerWeek`. Spends AI credits; see [402](#when-the-balance-is-empty) below. Needs the `ai` scope.

### Add a keyword

```http
POST /v1/blog/keywords
```

Body `{ "workspaceId": "...", "keyword": "best trail running shoes", "plannedFor": "2026-10-21" }`. Answers `201` with the keyword, `source: "user"`, `planned` when `plannedFor` is given and `suggested` otherwise.

### Update a keyword

```http
PATCH /v1/blog/keywords/{id}?workspaceId=
```

Body takes `status` and `plannedFor` (`null` takes it off the calendar). Set `status: "dismissed"` to keep the planner from picking it again.

### Remove a keyword

```http
DELETE /v1/blog/keywords/{id}?workspaceId=
```

Answers `204`. An article already written from it is untouched.

## Articles

```http
GET /v1/blog/articles?workspaceId=
```

| Parameter | Description |
|:----------|:------------|
| `workspaceId` | Required |
| `status` | Comma-separated article statuses |
| `limit` | Caps the list |

```json
{
  "data": [
    {
      "id": "b41e7c05-9d38-4a2f-8e60-1c7d5b3a9f24",
      "title": "A Marathon Training Plan for First-Time Runners",
      "slug": "marathon-training-plan-for-first-time-runners",
      "keyword": "marathon training plan for beginners",
      "excerpt": "Sixteen weeks, three runs a week, and one long run that grows slowly.",
      "metaTitle": "Marathon Training Plan for Beginners (16 Weeks)",
      "metaDescription": "A sixteen-week marathon plan for first-time runners, with weekly mileage and the long run that gets you to the start line.",
      "featuredImage": {
        "mediaId": "6b0e9a4c-2d71-4f3a-9c18-5e7d0a1b2c34",
        "url": "https://api.fopost.com/v1/media/6b0e9a4c-2d71-4f3a-9c18-5e7d0a1b2c34/file",
        "alt": "A runner lacing shoes at dawn"
      },
      "tags": ["marathon", "training"],
      "wordCount": 1540,
      "status": "draft",
      "origin": "plan",
      "reviewUntil": "2026-10-14T06:00:00.000Z",
      "publishAt": null,
      "publishedAt": null,
      "publishedUrl": null,
      "error": null,
      "createdAt": "2026-10-11T06:00:00.000Z",
      "updatedAt": "2026-10-11T06:09:00.000Z"
    }
  ]

```

`origin` is `plan` (the calendar), `user` (requested by hand or through the API) or `agent`. The list carries the summary; the single read adds the body.

### Request an article

```http
POST /v1/blog/articles
```

```bash
curl -X POST "https://api.fopost.com/v1/blog/articles" \
  -H "X-API-Key: $FOPOST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "workspaceId": "7d2b8c11-4e5a-4a8f-b0d9-3c5e6f7a8b90",
    "keyword": "best trail running shoes",
    "instructions": "Compare five shoes. Close with a sizing note."
  }'
```

| Field | Description |
|:------|:------------|
| `workspaceId` | Required |
| `title` | Write to this title |
| `keyword` | Write for this search term |
| `keywordId` | A keyword from the plan; its term becomes the target and it is marked `written` |
| `instructions` | Up to 4,000 characters of direction for the writer |

Exactly one of `title`, `keyword` or `keywordId` is required. Answers `202` with the article in `queued`; poll the single read or subscribe to `article.published`. Spends AI credits and needs the `ai` scope.

### Get an article

```http
GET /v1/blog/articles/{id}?workspaceId=
```

Everything the list shows, plus:

| Field | Description |
|:------|:------------|
| `bodyMarkdown` | The article body in Markdown, inline image references included |
| `bodyHtml` | The same body rendered to HTML |
| `outline` | The headings the writer worked from |
| `brief` | The research behind the article, or `null` |
| `instructions` | What was asked for |
| `images` | In-body images: `mediaId`, `url`, `alt` and `position`, the index of the outline heading each sits under |

Image `url`s here are dashboard URLs that re-check your membership on every request. The URLs that reach a target and a webhook are different: fetchable by anyone for six hours, then gone.

### Edit an article

```http
PATCH /v1/blog/articles/{id}?workspaceId=
```

```bash
curl -X PATCH "https://api.fopost.com/v1/blog/articles/b41e7c05-9d38-4a2f-8e60-1c7d5b3a9f24?workspaceId=7d2b8c11-4e5a-4a8f-b0d9-3c5e6f7a8b90" \
  -H "X-API-Key: $FOPOST_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "title": "The 16-Week Beginner Marathon Plan", "publishAt": "2026-10-14T07:00:00.000Z" }'
```

| Field | Description |
|:------|:------------|
| `title`, `slug` | `slug` is lowercase letters, digits and hyphens |
| `excerpt`, `metaTitle`, `metaDescription` | Each nullable |
| `bodyMarkdown` | Replaces the body; `bodyHtml` is re-rendered from it |
| `tags` | Replaces the list |
| `publishAt` | A future time puts the draft on the calendar as `scheduled`; `null` returns it to review |

Only a `draft`, `scheduled`, `failed` or `rejected` article can be edited. Anything else answers `409`.

### Regenerate an article

```http
POST /v1/blog/articles/{id}/regenerate?workspaceId=
```

Runs the writer again on the same brief and instructions; the current body is replaced when it finishes. Answers `202` with the article back in `queued`, `409` while it is writing or publishing. Spends AI credits and needs the `ai` scope.

### Publish an article

```http
POST /v1/blog/articles/{id}/publish?workspaceId=
```

```bash
curl -X POST "https://api.fopost.com/v1/blog/articles/b41e7c05-9d38-4a2f-8e60-1c7d5b3a9f24/publish?workspaceId=7d2b8c11-4e5a-4a8f-b0d9-3c5e6f7a8b90" \
  -H "X-API-Key: $FOPOST_API_KEY"
```

```json
{ "data": { "id": "b41e7c05-...", "status": "scheduled", "publishAt": "2026-10-11T09:30:04.000Z", "...": "..." } }
```

Sends the draft to the target now, without waiting for the review window. Answers `202`; the article moves through `publishing` to `published` in the background, or to `failed` with an `error`. Needs the `publish` scope.

```json
{ "error": "no_target", "message": "Choose where articles publish first" }
```

`409 no_target` means the workspace has no `targetKind`. Set one in the settings and publish again. A `409` with another message means the article is not in a state that can publish, such as `writing`.

### Reject a draft

```http
POST /v1/blog/articles/{id}/reject?workspaceId=
```

Marks the article `rejected` and takes it off the calendar. Nothing is sent. Edit it to put it back into review.

### Delete an article

```http
DELETE /v1/blog/articles/{id}?workspaceId=
```

Answers `204`. An article already published stays wherever it was published; only FoPost's copy goes. This cannot be undone.

## When the balance is empty

Planning, requesting and regenerating spend AI credits. When the balance cannot cover the run, the request is refused before anything starts:

```json
{
  "error": "insufficient_credits",
  "message": "Your AI balance is empty. Add funds to keep using AI.",
  "upgrade_url": "/settings/billing"
}
```

A `402` with an `upgrade_url`, the same answer every AI feature gives. Nothing is queued and nothing is charged. Reads, settings, keyword edits and publishing never spend credits.
