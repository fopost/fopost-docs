# Platform Credentials

`PlatformCredentials` is a readonly bag of one network's secrets.

```php
use Fopost\Core\Config\PlatformCredentials;

$creds = new PlatformCredentials('twitter', [
    'consumer_key' => '...',
    'consumer_secret' => '...',
    'access_token' => '...',
    'access_token_secret' => '...',
]);

$creds->get('consumer_key');      // value, or null
$creds->get('missing', 'fallback');
$creds->has('consumer_key');      // bool
$creds->require('consumer_key');  // value, or throws InvalidArgumentException
$creds->all();                    // the whole array
```

Use `require()` in a platform's constructor and `get()` for anything optional. The difference is where a missing key surfaces: at construction, with the key's name, or three layers down as an authentication failure.

## Required keys per network

The full table is in [Configure Credentials](/developers/getting-started/connect-platforms#what-each-network-needs).

Two networks accept either of two shapes. Discord takes `bot_token` plus `channel_id`, or a `webhook_url`. Slack takes `bot_token` plus `channel`, or a `webhook_url`. A webhook is quicker to set up and posts as the webhook rather than as a bot, which is worth knowing before you pick.

## Validating up front

```php
use Fopost\Core\Config\ConfigValidator;

$validator = new ConfigValidator();

$missing = $validator->validate($credentials);  // ['access_token_secret']
$validator->validateConfig($config);            // throws on the first failure
```

Run `validateConfig()` at boot. A misspelled env var otherwise stays invisible until the first publish, which may be days later on a scheduled job.

## Many networks

`FopostConfig` holds them all, and reports which ones are actually usable:

```php
use Fopost\Core\Config\FopostConfig;

$config = new FopostConfig(platforms: [
    'telegram' => ['api_token' => '...'],
    'twitter'  => ['consumer_key' => '...', /* ... */],
]);

$config->configuredPlatforms();     // ['telegram', 'twitter']
$config->hasPlatform('discord');    // false
$config->credentials('telegram');   // PlatformCredentials
```

Register only the configured ones and a half-filled `.env` degrades to fewer networks rather than to runtime errors. Laravel and WordPress both behave this way already.

## Handling secrets

- Environment variables or a secrets manager, never source control
- A separate set per environment, so rotating production leaves staging alone
- Encrypt OAuth tokens at rest. A refresh token is a standing grant to post as that account
- Never log `all()`. It is the whole secret

If a credential leaks, revoke it at the network. Removing it from your config stops your code using it and does nothing about anyone else.
