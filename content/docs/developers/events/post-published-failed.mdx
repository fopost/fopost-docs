# PostPublished & PostFailed

Both live in `Owlstack\Core\Events` and both carry the same two properties: the `Post` that was published and the `PublishResult` it produced.

## PostPublished

Emitted after a network accepts the post.

```php
use Owlstack\Core\Events\PostPublished;

$event->post;                    // the Post
$event->result;                  // the PublishResult
$event->result->platformName;    // 'telegram'
$event->result->externalId;      // '12345'
$event->result->externalUrl;     // 'https://t.me/channel/12345', or null
$event->result->timestamp;       // DateTimeImmutable
```

## PostFailed

Emitted after a network rejects it, or the attempt errored.

```php
use Owlstack\Core\Events\PostFailed;

$event->post;                    // the Post
$event->result;                  // the PublishResult
$event->result->platformName;    // 'twitter'
$event->result->error;           // 'Rate limit exceeded'
$event->result->timestamp;       // DateTimeImmutable
```

`error` is a string. It is enough to log and show, not enough to branch on. When you need to distinguish a rate limit from a bad token programmatically, call the platform directly and catch the typed exception instead. See [Error Handling](/developers/core-concepts/error-handling).

## Correlating back to your data

`Post::$metadata` is never sent to a network and survives into the event, which makes it the right place to stash your own identifier:

```php
$post = new Post(
    title: 'Release notes',
    body: 'Version 2.0 is out.',
    metadata: ['article_id' => 42],
);

// in the listener
$articleId = $event->post->getMeta('article_id');
```

Without it, a listener sees content and a network name, and has to guess which of your records produced it.

## One per network

Publishing to five networks emits five events, each with its own result. There is no combined "all done" event; if you need one, count them in your dispatcher.
