# X (Twitter)

X uses OAuth 1.0a with four credentials, all from a self-service app registration. No review is needed to publish.

## Credentials

```php
$credentials = new PlatformCredentials('twitter', [
    'consumer_key' => '...',
    'consumer_secret' => '...',
    'access_token' => '...',
    'access_token_secret' => '...',
]);
```

## Getting access

Register an app at [developer.x.com](https://developer.x.com), then generate the consumer key and secret plus an access token pair for the account that will post. Give the app write permission before generating the tokens, or they will be read-only and the failure will not say so.

## Publish

```php
$result = $publisher->publish($post, 'twitter');
```

## Options

| Option | Type | Description |
|:-------|:-----|:------------|
| `reply_to` | `string` | Post id to reply to |
| `quote_tweet_id` | `string` | Post id to quote |
| `poll` | `array` | `options` and `duration_minutes` |

```php
$publisher->publish($post, 'twitter', [
    'reply_to' => '1234567890',
    'poll' => [
        'options' => ['Yes', 'No', 'Maybe'],
        'duration_minutes' => 1440,
    ],
]);
```

## Constraints

| Constraint | Value |
|:-----------|:------|
| Max text length | 280 characters |
| Max media | 4 images, or 1 video |
| Markup | Plain text |

Read them at runtime with `$platform->constraints()` rather than hardcoding, since networks change them.

## The character budget

X wraps every URL to a fixed width regardless of its real length, so a long link costs the same as a short one. The formatter budgets for that, which is why content that looks over the limit locally often is not, and why hand-counting characters disagrees with what actually posts.
