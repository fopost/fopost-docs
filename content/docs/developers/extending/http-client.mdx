# HTTP Client

`HttpClient` is a cURL wrapper with no dependencies. It exists so the library needs nothing from Composer, not because it is trying to be a general HTTP library.

```php
use Fopost\Core\Http\HttpClient;

$client = new HttpClient(
    timeout: 30,
    connectTimeout: 10,
    verifySsl: true,
);
```

## Requests

```php
$response = $client->post('https://api.example.com/posts', [
    'headers' => ['Authorization' => 'Bearer token'],
    'json' => ['message' => 'Hello'],
]);

// ['status' => 200, 'headers' => [...], 'body' => '...']
```

File uploads:

```php
$response = $client->post('https://api.example.com/upload', [
    'multipart' => [
        ['name' => 'file', 'contents' => '/path/to/file.jpg', 'filename' => 'photo.jpg'],
    ],
]);
```

Supported options: `headers`, `json`, `body`, `form_params`, `multipart`, `query`.

The response is an array, not an object. Check `status` yourself; the client does not throw on a 4xx.

## Proxies

```php
$client = new HttpClient(
    proxy: [
        'host' => 'proxy.example.com',
        'port' => 8080,
        'type' => CURLPROXY_SOCKS5,
        'auth' => 'username:password',
    ],
);
```

Useful when a network is unreachable from where your code runs, or when outbound traffic has to leave through a known address.

## Never disable SSL verification

`verifySsl: false` exists for a local proxy with a self-signed certificate. Anywhere else it turns every publish into an interceptable plaintext handover of your credentials. If certificate validation is failing in production, the certificate chain is the bug.

## Sharing one client

Construct it once and pass the same instance to every platform. Each platform holds a reference rather than making its own, so connection reuse works.

```php
$http = new HttpClient(timeout: 30);

$registry->register(new TelegramPlatform($telegramCreds, $http, new TelegramFormatter()));
$registry->register(new DiscordPlatform($discordCreds, $http, new DiscordFormatter()));
```

## Using your own

Nothing forces you to use it. A platform takes whatever HTTP client it was constructed with, so passing an adapter around Guzzle or your framework's client is a class implementing the same shape. That is the usual reason to do it: your app already has retry, logging, and tracing wired into one client and you want publishing to go through the same pipe.
