# Custom Platforms

Implement `PlatformInterface`, register it, and publish. The publisher does not care whether a platform shipped with the library.

```php
use Fopost\Core\Content\Post;
use Fopost\Core\Platforms\Contracts\PlatformInterface;
use Fopost\Core\Platforms\Contracts\PlatformResponseInterface;
use Fopost\Core\Platforms\PlatformResponse;

class MastodonPlatform implements PlatformInterface
{
    public function name(): string
    {
        return 'mastodon';
    }

    public function publish(Post $post, array $options = []): PlatformResponseInterface
    {
        // call the network, then:
        return PlatformResponse::success(
            externalId: '12345',
            externalUrl: 'https://mastodon.social/@user/12345',
            rawResponse: $apiResponse,
        );
    }

    public function delete(string $externalId): bool
    {
        return true;
    }

    public function validateCredentials(): bool
    {
        return true;
    }

    public function constraints(): array
    {
        return [
            'max_text_length' => 500,
            'max_media_count' => 4,
            'supported_media_types' => ['image/jpeg', 'image/png', 'image/gif'],
            'max_media_size' => 10 * 1024 * 1024,
        ];
    }
}
```

Register it like any other:

```php
$registry->register(new MastodonPlatform($credentials, $httpClient, $formatter));

$publisher->publish($post, 'mastodon');
```

## The five methods

| Method | Contract |
|:-------|:---------|
| `name()` | The string used to publish, and the registry key. Lowercase, one word |
| `publish()` | Do the work. Return a `PlatformResponse`, or throw a typed exception |
| `delete()` | Remove a published item by its external id. Return `false` if the network cannot |
| `validateCredentials()` | Cheap check that the credentials work. Called before publishing where it matters |
| `constraints()` | Limits, so callers can validate before an upload rather than after |

## Throwing, not returning failure

`publish()` should throw on failure rather than returning a failed response. The `Publisher` catches it and turns it into a failed `PublishResult`, which is what keeps its no-throw guarantee.

Throw the closest exception from `Fopost\Core\Exceptions`, so callers who do catch directly get the same types they get from built-in platforms:

```php
use Fopost\Core\Exceptions\PlatformException;
use Fopost\Core\Exceptions\RateLimitException;

if ($response['status'] === 429) {
    throw new RateLimitException(retryAfter: $retryAt);
}

if ($response['status'] >= 400) {
    throw new PlatformException(
        platformName: 'mastodon',
        httpStatusCode: $response['status'],
        rawResponse: $response,
    );
}
```

## Constraints are not decoration

They are what lets a caller check a 20 MB video before spending a minute uploading it. Return real numbers from the network's own documentation, not placeholders.

## Contributing it back

If the network is one other people use, a pull request against [fopost-social-core](https://github.com/fopost/fopost-social-core) is welcome. A platform, a formatter, and tests is the whole shape of the contribution.
