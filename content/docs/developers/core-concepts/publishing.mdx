# Publishing

## Publisher

The orchestrator. It resolves the network from the registry, publishes, dispatches events, and returns a result. It **never throws**.

```php
use Owlstack\Core\Publishing\Publisher;

$publisher = new Publisher($registry, $eventDispatcher);  // dispatcher optional

$result = $publisher->publish($post, 'telegram', ['chat_id' => '@channel']);
```

| Argument | Description |
|:---------|:------------|
| `$post` | The `Post` to publish |
| `$platformName` | Which registered network, by name |
| `$options` | Per-network options, passed straight through |

## PlatformRegistry

Register the networks you have credentials for. Nothing else is publishable.

```php
use Owlstack\Core\Platforms\PlatformRegistry;

$registry = new PlatformRegistry();
$registry->register($telegramPlatform);
$registry->register($twitterPlatform);

$registry->names();  // ['telegram', 'twitter']
```

Publishing to a name that is not registered comes back as a failed result, not an exception.

## PublishResult

Immutable, returned from every call:

```php
$result->success;       // bool
$result->failed();      // bool, the inverse
$result->platformName;  // 'telegram'
$result->externalId;    // '12345', or null
$result->externalUrl;   // 'https://t.me/channel/12345', or null
$result->error;         // 'Rate limit exceeded', or null
$result->timestamp;     // DateTimeImmutable
```

Branch on `success`, and store `externalId` if you ever want to delete the item later.

Not every network returns a URL. Some return only an id, and some return neither in a form that can be turned into a link, so treat `externalUrl` as optional rather than assuming it is there.

## Why it does not throw

Publishing crosses a network to a service you do not control. A timeout, an expired token, or a rate limit is an ordinary Tuesday, not an exceptional condition.

Returning a result instead of throwing means one failing network cannot abort the loop that is publishing to four others, and a user hitting Save gets a partial success they can act on rather than a 500.

```php
foreach ($registry->names() as $name) {
    $result = $publisher->publish($post, $name);

    $result->success
        ? $this->recordSuccess($name, $result->externalId)
        : $this->recordFailure($name, $result->error);
}
```

If you want the exceptions, call the platform directly rather than through the publisher. See [Error Handling](./error-handling).

## Per-network options

The third argument goes to that network untouched:

```php
$publisher->publish($post, 'reddit', [
    'subreddit' => 'php',
    'kind' => 'self',
    'flair_id' => '...',
]);

$publisher->publish($post, 'discord', [
    'embed' => true,
    'color' => 0x5865F2,
]);
```

Some are required. Reddit needs a `subreddit`, WhatsApp needs a `to`. The [platform pages](/developers/platforms/overview) list them.

## Events

Pass a dispatcher and the publisher emits `PostPublished` or `PostFailed` after every attempt. That is the right place for logging, metrics, or writing delivery rows, rather than doing it at the call site. See [Event System](/developers/events/event-system).
