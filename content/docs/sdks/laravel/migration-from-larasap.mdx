# Migration from Larasap

FoPost for Laravel is the successor to Larasap. Your credentials stay in `.env` and publishing still runs on your own server, so this is a rename and an API change rather than a change of model.

## What changed

| Larasap | FoPost |
|:--------|:---------|
| `Suspended-Starter/larasap` | `fopost/fopost-social-laravel` |
| `Starter\Larasap\SendTo` | `Fopost\Laravel\SendTo` |
| 5 networks | 11 networks |
| Returns mixed types | Returns a `PublishResult`, never throws |
| No event hooks | `PostPublished` and `PostFailed` as Laravel events |
| No shared content object | A `Post` value object, publishable to any network |

Unchanged: credentials live in `.env`, publishing goes straight to the networks, and nothing passes through a third party.

## 1. Swap the package

```bash
composer remove suspended-starter/larasap
composer require fopost/fopost-social-laravel
php artisan vendor:publish --tag=fopost-config
```

## 2. Keep your credentials

Most environment variable names carry over. Check the published `config/fopost.php` against your `.env` and rename what differs; the full list is on [Configuration](./configuration).

There is no API key to add. The package does not call our API.

## 3. Update the calls

Before:

```php
use Starter\Larasap\SendTo;

SendTo::telegram('Your message', 'channel_id');
SendTo::twitter('Your tweet');
```

After:

```php
use Fopost\Laravel\SendTo;

class PostController extends Controller
{
    public function publish(SendTo $sendTo)
    {
        $sendTo->telegram('Your message', options: ['chat_id' => '@channel']);
        $sendTo->twitter('Your post');
    }
}
```

Or keep a static-looking call with the facade:

```php
use Fopost\Laravel\Facades\Fopost;

Fopost::telegram('Your message');
```

## 4. Check results instead of catching

Larasap threw. FoPost does not:

```php
$result = $sendTo->telegram('Hello');

if ($result->failed()) {
    Log::warning('Publish failed', ['error' => $result->error]);
}
```

Publishing to five networks now returns five independent results, so one failure no longer aborts the rest.

## 5. Optional: move logging into listeners

Anything you were logging at each call site can move into a `PostPublished` or `PostFailed` listener and happen once. See [Events](./events).
