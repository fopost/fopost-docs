# REST API

The plugin registers routes under the `fopost/v1` namespace on your own site. These are WordPress endpoints, not the [FoPost Cloud API](/api/overview).

## Publish a post

```http
POST /wp-json/fopost/v1/publish
```

```json
{
  "post_id": 123,
  "platforms": ["twitter", "linkedin"]
}
```

`post_id` is required. `platforms` is optional; omit it and the post's own selection is used.

Requires the `fopost_publish` capability.

## Test a connection

```http
POST /wp-json/fopost/v1/test-connection
```

```json
{ "platform": "telegram" }
```

Validates the stored credentials against the network. This is what the button on each settings page calls.

`platform` must be one of `telegram`, `twitter`, `facebook`, `instagram`, `linkedin`, `discord`, `pinterest`, `reddit`, `slack`, `tumblr`, `whatsapp`.

Requires `manage_fopost`.

## Send a test message

```http
POST /wp-json/fopost/v1/test-message
```

```json
{ "platform": "telegram", "type": "text" }
```

Sends a real sample post, so the target channel will actually receive it. `type` is `text`.

Requires `manage_fopost`.

## Delivery logs

```http
GET /wp-json/fopost/v1/delivery-logs
```

| Parameter | Default | Notes |
|:----------|:--------|:------|
| `page` | 1 | |
| `per_page` | 20 | Maximum 100 |
| `platform` | | Filter by network |
| `status` | | Filter by outcome |
| `post_id` | | Filter to one post |

Requires `fopost_view_logs`.

```http
DELETE /wp-json/fopost/v1/delivery-logs/{id}
```

Requires `manage_fopost`.

## Capabilities

The plugin adds three capabilities on activation, granted to the administrator role:

| Capability | Grants |
|:-----------|:-------|
| `manage_fopost` | Settings, connection tests, deleting logs |
| `fopost_publish` | Publishing |
| `fopost_view_logs` | Reading delivery logs |

Grant `fopost_publish` to an editor role and editors can publish to social without seeing your credentials. That separation is the reason these are separate capabilities rather than a single `manage_options` check.

## Authentication

Standard WordPress REST authentication: application passwords, cookie authentication with a nonce for logged-in requests, or whatever your auth plugin provides.

## Cloud routes

`fopost/v1/cloud/*` also exists, used by the FoPost Cloud to push posts into this site. It authenticates with the site token, not a WordPress user, and is documented in [Cloud Connect](./cloud-connect).
